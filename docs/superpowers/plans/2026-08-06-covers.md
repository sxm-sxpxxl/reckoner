# Meeting Covers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Обложка встречи: загрузка перетаскиванием и кликом, сжатие на клиенте, хранение в Postgres, раздача с кэшированием.

**Architecture:** Байты лежат в `meetings.cover_bytes` (`bytea`) — колонка уже есть в схеме вместе с `cover_mime` и `cover_version`. Внешнего хранилища нет намеренно: на бесплатном Render нет постоянного диска, а поднимать S3 ради нескольких фотографий — лишняя сущность. Клиент уменьшает картинку до отправки, сервер отбивает всё, что всё равно слишком велико.

**Tech Stack:** axum 0.7, sqlx 0.9, canvas API на клиенте.

## Решения, принятые до начала

**Лимит тела у обложек свой.** JSON-роутер ограничен 64 КБ (`JSON_BODY_LIMIT`), и картинка
в него не пролезет. Маршрут обложки получает собственный `DefaultBodyLimit` на 1 МБ, а внутри
хендлера — ещё проверка длины, чтобы ответить `413` своей формой тела, а не пустым отказом слоя.

**Тип проверяем по байтам, а не по `Content-Type`.** Заголовок присылает клиент, и ему верить
нельзя: подпись PNG/JPEG в первых байтах — единственное, что действительно говорит, что это
картинка. Иначе `415` не защищает ни от чего.

**`cover_version` растёт при каждой замене** и уходит в query-параметр `?v=N`. Так ответ можно
кэшировать «навсегда» (`immutable`), а замена всё равно видна сразу: у новой картинки другой URL.

**`ETag` — от версии, а не от хеша байтов.** Хеш пришлось бы считать на каждый запрос; версия
меняется ровно тогда, когда меняется картинка, и этого достаточно.

**Сжатие на клиенте обязательно, а не «на всякий случай».** Фотография с телефона — 3–5 МБ,
и без уменьшения она не пройдёт ни лимит, ни здравый смысл: 0,5 ГБ Neon кончились бы на сотне
встреч. Клиент приводит к 1600 px по большей стороне и JPEG q0.82.

**Удаление обложки — отдельный метод.** `DELETE` возвращает встречу целиком, как остальные
мутации.

### Task 2: Ручки обложки

- [ ] **Step 1: Расширить `ApiError`**

Нужны два новых варианта — `TooLarge` (`413`) и `UnsupportedMedia` (`415`), оба с той же формой
тела (`{"error": "too-large"}` / `{"error": "unsupported-media"}`). Дописать тесты в
`error.rs` рядом с существующими.

- [ ] **Step 2: Написать падающие тесты ручек**

Проверить: загрузка PNG и JPEG проходит и поднимает версию; тело больше 1 МБ → `413`;
не-картинка (например, текст) → `415`; загрузка в несуществующую встречу → `404`;
`GET` без обложки → `404`; `DELETE` возвращает встречу с `hasCover: false`.

Подписи для тестов: PNG — `\x89PNG\r\n\x1a\n`, JPEG — `\xFF\xD8\xFF`.

- [ ] **Step 3: Реализовать**

```rust
/// Потолок тела обложки. Клиент сжимает до ~500 КБ, мегабайт — запас
/// на неудачное сжатие. Не путать с `JSON_BODY_LIMIT`: там 64 КБ, и картинка
/// в них не пролезет.
const COVER_BODY_LIMIT: usize = 1024 * 1024;

/// Тип определяется по первым байтам, а не по заголовку `Content-Type`:
/// заголовок присылает клиент, и доверять ему — значит не проверять вовсе.
fn sniff_mime(bytes: &[u8]) -> Option<&'static str> {
    if bytes.starts_with(b"\x89PNG\r\n\x1a\n") {
        return Some("image/png");
    }
    if bytes.starts_with(&[0xFF, 0xD8, 0xFF]) {
        return Some("image/jpeg");
    }

    None
}
```

`GET` отдаёт байты с `ETag: "<version>"`,
`Cache-Control: public, max-age=31536000, immutable` и отвечает `304`, если
`If-None-Match` совпал. `PUT` пишет обложку, дописывает лог «Обновлена обложка встречи»
и возвращает встречу; `DELETE` — «Обложка удалена».

Маршрут вешается **до** `DefaultBodyLimit` JSON-роутера и получает свой лимит:

```rust
        .route(
            "/api/meetings/:id/cover",
            get(covers::show).put(covers::upload).delete(covers::destroy),
        )
        .layer(DefaultBodyLimit::max(COVER_BODY_LIMIT))
```

Порядок слоёв здесь несёт смысл: в axum ближайший к маршруту слой применяется последним,
поэтому лимит обложки должен объявляться на своём под-роутере, а не поверх общего.
