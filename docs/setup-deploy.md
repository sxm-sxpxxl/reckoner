# Деплой

Что нужно сделать руками, чтобы приложение оказалось в интернете. Всё бесплатно, карта не нужна.

Три части на трёх хостингах: фронтенд на GitHub Pages, бэкенд на Render, база — бранч `main`
в Neon. Связаны они тремя переменными, и ошибка в любой ломает связь целиком.

## Порядок важен

Тут кольцо: фронтенду нужен адрес бэкенда, а бэкенду — адрес фронтенда. Разрывается оно так:

1. Поднять бэкенд **без** `ALLOWED_ORIGIN` → узнать его адрес.
2. Собрать фронт с этим адресом → узнать адрес Pages.
3. Вернуться в Render и задать `ALLOWED_ORIGIN`.

Если сделать иначе, на третьем шаге придётся всё равно возвращаться, но с уже сломанным сайтом
и непонятной ошибкой в консоли браузера.

---

## Шаг 1. Строка подключения к проду

В консоли Neon открыть проект `reckoner`, бранч **`main`** (тот самый корневой, который создался
первым) и нажать **Connect**.

Требования к строке те же, что для `dev` и `test`:

- **Connection pooling выключен** — в имени хоста не должно быть `-pooler`;
- параметр `channel_binding=require` из строки убрать, оставить `?sslmode=require`.

Почему без пулера — в [`setup-neon.md`](setup-neon.md), шаг 3.

Строку никуда не вставлять, она понадобится на следующем шаге.

## Шаг 2. Сервис на Render

1. Зарегистрироваться на [render.com](https://render.com) через GitHub.
2. **New → Blueprint**, выбрать репозиторий `reckoner`. Render найдёт `render.yaml` в корне
   и предложит создать сервис `reckoner-api`.
3. Он спросит значения двух переменных:
   - `DATABASE_URL` — строка из шага 1;
   - `ALLOWED_ORIGIN` — **пока оставить пустой**. Заполним на шаге 5.
4. Нажать создание и ждать. **Первая сборка идёт долго**, десять–пятнадцать минут: Rust
   компилируется с нуля. Последующие быстрее — слой с зависимостями кэшируется.

Когда деплой позеленеет, наверху будет адрес вида `https://reckoner-api.onrender.com`.
Проверить:

```bash
curl https://reckoner-api.onrender.com/api/health
```

Ожидается `{"status":"ok"}`. Если вместо этого ошибка — открыть **Logs** в панели: сервер
печатает причину человеческим текстом и падает сразу, а не отдаёт 500 на каждый запрос.

## Шаг 3. Переменная с адресом API

В GitHub: **Settings → Secrets and variables → Actions → Variables → New repository variable**.

- Name: `VITE_API_BASE_URL`
- Value: адрес из шага 2, **без слеша на конце** — `https://reckoner-api.onrender.com`

Это variable, а не secret: адрес и так виден в каждом запросе из браузера, прятать нечего.

## Шаг 4. Включить Pages

**Settings → Pages → Source: GitHub Actions.** Не «Deploy from a branch» — публикацией
занимается workflow.

После этого запустить сборку: **Actions → Pages → Run workflow**. Либо просто сделать любой
пуш в `master`.

Когда пройдёт, адрес сайта будет в результатах задачи `deploy` — вида
`https://ИМЯ.github.io/reckoner/`.

## Шаг 5. Закрыть CORS

Вернуться в Render, **Environment**, задать:

```
ALLOWED_ORIGIN = https://ИМЯ.github.io
```

Только схема и хост: **без** `/reckoner/` и **без** слеша на конце. Сравнение в CORS строковое,
и `https://имя.github.io/` никогда не совпадёт с `https://имя.github.io`.

Render перезапустит сервис. Если значение задано криво, сервис **не поднимется** — это
сознательно: молча оставить прод с открытым CORS хуже, чем упасть заметно. Причина будет
в логе прямым текстом.

## Шаг 6. Проверить

Открыть сайт, создать встречу, добавить участника и расход. Затем скопировать адрес встречи,
открыть в новой вкладке — должна открыться она, а не 404. Это проверка SPA-фолбэка.

---

## Что стоит знать

**Первый запрос после простоя висит 30–60 секунд.** Render усыпляет бесплатный сервис через
15 минут бездействия. Приложение это предусматривает: если сервер не ответил за пару секунд,
показывается экран «будим сервер». Друзьям стоит сказать заранее, иначе решат, что сайт сломан.

**Автодеплой.** Пуш в `master` пересобирает и бэкенд (Render), и фронт (Pages). Отдельно
ничего запускать не надо.

**Что где менять:**

| Что | Где |
| --- | --- |
| Строка базы, origin фронта | Render → Environment |
| Адрес API для фронта | GitHub → Actions variables |
| Всё остальное | код |

## Если что-то пошло не так

| Симптом | Причина |
| --- | --- |
| В браузере ошибка CORS | `ALLOWED_ORIGIN` со слешом на конце или с путём |
| Запросы уходят на `localhost` | не задана `VITE_API_BASE_URL`, либо Pages собрался до неё — перезапустить workflow |
| Прямая ссылка на встречу даёт 404 | не сработал шаг с `404.html`; проверить лог задачи Pages |
| Сервис на Render не поднимается | смотреть Logs: причина печатается текстом |
| `prepared statement "sqlx_s_N" already exists` | взята pooled-строка; убрать `-pooler` из хоста |
| Долгий первый запрос | сервис спал, это ожидаемо |
